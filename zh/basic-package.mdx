`场景模板` 决定场景界面上按钮、工具与菜单的组成与位置。应用一份场景模板之后得到的界面称为场景界面（旧称沉浸模式），与之相对的是传统界面。本文假定读者已经掌握场景插件与插件面板（index.html）的写法。插件编写完成之后，还需要一份模板，界面才会出现对应的入口。本文先说明模板包的文件构成，再给出一份可以导入的最小模板。

# 模板包的结构

模板包是扩展名为 `.mntemplate` 的压缩文件，解压之后的目录结构如下：

<Tree>
  <Tree.Folder name="起步-0.1.0.mntemplate" defaultOpen>
    <Tree.File name="template.json" />
    <Tree.File name="manifest.json" />
    <Tree.File name="localizations.json" />
    <Tree.Folder name="plugins" defaultOpen>
      <Tree.Folder name="mn.hello" defaultOpen>
        <Tree.File name="mnaddon.json" />
        <Tree.File name="index.html" />
        <Tree.File name="hello.png" />
      </Tree.Folder>
    </Tree.Folder>
  </Tree.Folder>
</Tree>

各文件的分工如下。

- `template.json`：模板配置。界面元素的组成、偏好的预设值、AI 任务的声明，都写在这份文件里。本文余下部分的讲解围绕这份文件展开。
- `manifest.json`：包目录。记录包的目标应用、包含的插件清单与所需的最低 MarginNote 版本。
- `localizations.json`：模板名称的多语言取值。
- `plugins/<插件id>/`：模板用到的插件，按插件 id 分目录，原样放进包内。

其中 `template.json` 与 `manifest.json` 是 MarginNote 识别模板所必需的。插件是模板的一部分，界面上的按钮、菜单项与面板都依赖插件，因此模板与插件一起分发。

# 最小模板

`template.json` 里只有 `id` 与 `name` 是必填字段：

```json template.json
{
  "id": "u-hello",
  "name": "你好世界"
}
```

`manifest.json` 由出包脚本生成，字段含义如下：

```json manifest.json
{
  "format": 1,
  "app": "MarginNote",
  "appVersion": "4.5.0",
  "exportedAt": 1700000000,
  "template": {
    "id": "u-hello",
    "name": "你好世界"
  },
  "plugins": [
    {
      "pluginID": "mn.hello",
      "folder": "mn.hello",
      "version": "0.1.0",
      "title": "你好世界"
    }
  ]
}
```

- `format`：包格式的版本号。
- `app` 与 `appVersion`：目标应用与所需的最低 MarginNote 版本。
- `template`：模板的 `id` 与 `name`，需与 `template.json` 一致。
- `plugins`：包内插件的清单。`pluginID` 与 `folder` 取插件的 `addonid`，`version` 与 `title` 取 `mnaddon.json` 中的同名字段。

`localizations.json` 按界面语言给出模板名称：

```json localizations.json
{
  "zh-Hans": {
    "你好世界": "你好世界"
  },
  "en": {
    "你好世界": "Hello World"
  }
}
```

<Note>
  模板界面上的文字（例如模态名称、笔与摘录工具的名称）按界面语言取值，模态的写法见[工具与模式](/zh/template-bottom)。取不到对应语言时改用英文。
</Note>

# 打包与导入

把上例中的文件按目录结构放进一个文件夹，压缩为 zip，再把扩展名改成 `.mntemplate`，便得到一个模板包。

导入步骤：点击 `设置` 右侧的三点按钮，选择 `插件`，再选择 `导入`。导入之后，模板出现在场景界面顶部的场景模板菜单里，位于 `我的场景模板` 一组中。带插件的包会一并安装插件。安装前逐项列出处理方式：本机没有的插件执行新安装，包内版本更新的插件替换本机的版本，同版本或本机更新的插件跳过安装。

<Note>
  未认证的插件需要在 `设置` 里允许之后才能安装。插件安装失败时，模板虽然导入了也无法使用。
</Note>

# 覆盖规则

模板中的每个位置都遵循同一条规则，这条规则称为覆盖规则：字段写出取值时，以写出的内容为准；留空表示不接管，MarginNote 保持现状。

这条规则决定了模板的写法：留空表示 MarginNote 保持现状，不表示清空。想让某个位置的条目比默认更少，必须把要保留的条目显式列出来。

因此不要先复制一份别人的模板再修改。复制会把对方模板的声明一并继承下来，且难以察觉。仓库里的起步模板曾经从一份复习模板整份复制，于是其中一直带着复习模板用的标签前缀、一个摘题按钮，以及一条要求插件写入特定字段的复习规则；而起步插件一个字段都不写，那条规则永远匹配不上。

每一篇后续文章都会重申这条规则，因为它决定了所有字段的解读方式。

<Warning>
  模板里的字段名或代号写错时，MarginNote 不会报错，而是静默忽略该条目，表现为对应的按钮没有出现。排查办法见[校验与排错](/zh/template-validate)。
</Warning>

# 身份字段

除 `id` 与 `name` 之外，`template.json` 顶层还有以下字段，用于控制模板本身：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `String` | 模板的唯一标识。 |
| `name` | `String` | 模板在界面上的名称。 |
| `schema` | `Int?` | 配置格式的版本号。留空表示不接管。 |
| `minAppVersion` | `String?` | 所需的最低 MarginNote 版本。留空表示不限制 MarginNote 版本。 |
| `base` | `String?` | 这份模板复制自哪一份系统场景模板。该字段由用户在模板编辑器（用于编辑场景模板配置的界面）中复制系统场景模板时产生，手写时无需填写。 |

`schema` 与 `minAppVersion` 都是版本检查字段。`schema` 检查配置格式的版本，只在配置格式整体换代时才需要改动；`minAppVersion` 检查 MarginNote 版本，模板用到 MarginNote 在某一版本之后才提供的能力时声明该字段，导入时，版本不足的 MarginNote 会拒绝该模板。文件导入同样会检查，不限于从模板库安装。

# 样例与模板库

模板可以附带一份样例，导入模板的人打开即可看到效果。相关字段如下：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `sample` | `Sample?` | 随模板分发的样例。 |
| `gallery` | `GallerySource?` | 该模板来自模板库的记录。 |

`Sample` 的字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `title` | `String` | 样例的标题。 |
| `summary` | `String?` | 样例的简介。 |
| `file` | `String` | 样例学习集文件的位置。 |
| `topicIds` | `[String]?` | 样例包含的学习集标识。 |
| `sizeBytes` | `Int?` | 样例文件的字节数。 |
| `language` | `String?` | 样例内容的语言。 |

`GallerySource` 的字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `String` | 模板库中的标识。 |
| `version` | `String` | 模板库中的版本号。 |

<Warning>
  样例中的全部卡片与文档会随模板一起分发，导入模板的人都能读到。添加样例之前需要确认内容可以公开。
</Warning>

# 逐级递进的样本

仓库的 `sdk/output/tools/starter/template/` 目录下放着逐级递进的模板样本，每一份只比前一份多一个概念。各级新增的内容见下表：

| 文件 | 新增内容 | 对应文章 |
| --- | --- | --- |
| `0-minimal.json` | 无。只有 `id` 与 `name`。 | 本文 |
| `1-bottom.json` | `bottom`，接管底部工具条 | [工具与模式](/zh/template-bottom) |
| `2-plugin.json` | `plugins`、`pluginConfigs`、`addon.` 代号 | [接入插件](/zh/template-plugins) |
| `3-full.json` | `aiTasks`，声明 AI 任务 | [AI 任务](/zh/template-ai) |

导入 `0-minimal.json` 之后，界面看起来与默认状态一致。这属于正常现象，因为这份模板没有接管任何位置。
