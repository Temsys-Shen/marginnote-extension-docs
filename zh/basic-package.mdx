`场景模板` 决定场景界面上按钮、工具与菜单的组成与位置。应用一份场景模板之后得到的界面称为场景界面（旧称沉浸模式），与之相对的是传统界面。

写完场景插件和插件面板（index.html）之后，还需要一份模板，界面上才会出现对应的入口。下面先说模板包的文件构成，再提供一份可以直接导入的最小模板。

# 模板包的结构

模板包是扩展名为 `.mntemplate` 的压缩文件，解压之后的目录结构如下：

<Tree>
  <Tree.Folder name="起步-0.1.0.mntemplate" defaultOpen>
    <Tree.File name="template.json" />
    <Tree.File name="manifest.json" />
    <Tree.File name="localizations.json" />
    <Tree.Folder name="plugins" defaultOpen>
      <Tree.Folder name="mn.hello" defaultOpen>
        <Tree.File name="mnaddon.json" />
        <Tree.File name="index.html" />
        <Tree.File name="hello.png" />
      </Tree.Folder>
    </Tree.Folder>
  </Tree.Folder>
</Tree>

各文件的用途：

- `template.json`：模板配置。界面元素的组成、偏好的预设值、AI 任务的声明，都写在这份文件里。以下先讲这份文件，再补充 `manifest.json` 与 `localizations.json`。
- `manifest.json`：包目录。记录包的目标应用、包含的插件清单与所需的最低 MarginNote 版本。
- `localizations.json`：模板名称的多语言取值。
- `plugins/<插件id>/`：模板用到的插件，按插件 id 分目录，原样放进包内。

其中 `template.json` 与 `manifest.json` 是 MarginNote 识别模板所必需的。界面上的按钮、菜单项与面板都由插件提供，因此模板与插件一起分发。

# 最小模板

`template.json` 里只有 `id` 与 `name` 是必填字段：

```json template.json
{
  "id": "u-hello",
  "name": "你好世界"
}
```

`manifest.json` 示例：

```json manifest.json
{
  "format": 1,
  "app": "MarginNote",
  "appVersion": "4.5.0",
  "exportedAt": 1700000000,
  "template": {
    "id": "u-hello",
    "name": "你好世界"
  },
  "plugins": [
    {
      "pluginID": "mn.hello",
      "folder": "mn.hello",
      "version": "0.1.0",
      "title": "你好世界"
    }
  ]
}
```

- `format`：包格式的版本号。
- `app` 与 `appVersion`：目标应用与所需的最低 MarginNote 版本。
- `template`：模板的 `id` 与 `name`，需与 `template.json` 一致。
- `plugins`：包内插件的清单。`pluginID` 与 `folder` 取插件的 `addonid`，`version` 与 `title` 取 `mnaddon.json` 中的同名字段。

`localizations.json` 按界面语言给出模板名称：

```json localizations.json
{
  "zh-Hans": {
    "你好世界": "你好世界"
  },
  "en": {
    "你好世界": "Hello World"
  }
}
```

<Note>
  模板界面上的文字（例如模态名称、笔与摘录工具的名称）按界面语言取值，模态的写法见[工具与模式](/zh/template-bottom)。取不到对应语言时改用英文。
</Note>

# 打包与导入

把上例中的文件按目录结构放进一个文件夹，压缩为 zip，再把扩展名改成 `.mntemplate`，便得到一个模板包。

导入步骤：进入场景界面，打开顶部的 `场景模板` 菜单，选择 `编辑场景模板…`，在左栏底部选择 `管理场景模板`，再选择 `导入场景模板…`。导入之后，模板出现在场景界面顶部的场景模板菜单里，位于 `我的场景模板` 一组中，并立即成为当前模板。带插件的包会一并安装插件：本机未安装的插件执行安装，包内版本高于本机版本的替换本机版本，版本相同或本机版本更高的跳过安装。

<Note>
  未认证的插件需要先在 `设置` 里允许才能安装；未允许时，整份模板包会被拒绝导入，不会留下半份模板。模板导入成功后插件被卸载或取消允许时，模板仍然存在，模板编辑器里该插件标注为 `(不可用)`。
</Note>

# 覆盖规则

模板中的每个位置都遵循同一条规则，这条规则称为覆盖规则：字段写出取值时，以写出的内容为准；留空表示不接管，MarginNote 保持现状。

这条规则决定了模板的写法：留空表示 MarginNote 保持现状，不表示清空。想让某个位置的条目比默认更少，必须把要保留的条目显式列出来。

因此不要先复制现成模板再修改，复制会把原模板的声明一并继承下来，且难以察觉。例如复制一份复习模板得到的模板，会继承复习用的标签前缀、摘题按钮，以及一条要求插件写入特定字段的复习规则（标签前缀见[AI 任务](/zh/template-ai)，复习规则见[行为设置](/zh/template-settings)）；如果配套插件不写这个字段，这条规则就永远匹配不上。

<Warning>
  模板里的字段名或代号写错时，MarginNote 不会报错，而是静默忽略该条目，表现为对应的按钮没有出现。字段的取值类型写错时，整份模板无法解析，MarginNote 回退到默认模板。排查办法见[校验与排错](/zh/template-validate)。
</Warning>

# 身份字段

除 `id` 与 `name` 之外，`template.json` 顶层还有以下字段，用于控制模板本身：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `String` | 模板的唯一标识。 |
| `name` | `String` | 模板在界面上的名称。 |
| `schema` | `Int?` | 配置格式的版本号。留空表示不接管。 |
| `minAppVersion` | `String?` | 所需的最低 MarginNote 版本。留空表示不限制 MarginNote 版本。 |
| `base` | `String?` | 这份模板的来源，即复制自的系统场景模板。在模板编辑器（编辑场景模板配置的界面）中复制系统场景模板时，该字段自动产生；手写模板时无需填写。 |

`schema` 与 `minAppVersion` 都是版本检查字段。`schema` 检查配置格式的版本，只在配置格式整体变更时才需要改动；`minAppVersion` 检查 MarginNote 版本，模板用到 MarginNote 在某一版本之后才提供的能力时声明该字段，导入时，版本不足的 MarginNote 会拒绝该模板。文件导入同样会检查，不限于从模板库安装。

# 样例与模板库

模板可以附带一份样例，导入模板的人打开即可看到效果。样例文件放在包内 `sample/` 目录下：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `sample` | `Sample?` | 随模板分发的样例。 |
| `gallery` | `GallerySource?` | 该模板来自模板库的记录。 |

`Sample` 的字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `title` | `String` | 样例的标题。 |
| `summary` | `String?` | 样例的简介。 |
| `file` | `String` | 样例学习集文件在包内 `sample/` 目录下的文件名。 |
| `topicIds` | `[String]?` | 样例包含的学习集标识。 |
| `sizeBytes` | `Int?` | 样例文件的字节数。 |
| `language` | `String?` | 样例内容的语言。 |

`GallerySource` 的字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `String` | 模板库中的标识。 |
| `version` | `String` | 模板库中的版本号。 |

<Warning>
  样例中的全部卡片与文档会随模板一起分发，导入模板的人都能读到。添加样例之前需要确认内容可以公开。
</Warning>

# 从最小模板往上加

模板可以逐步扩充：只有 `id` 与 `name` 的模板不接管任何位置，导入后界面不会有任何变化，MarginNote 保持默认行为。每多写一个字段，就多接管一处：

| 想接管的内容 | 要写的字段 | 对应文章 |
| --- | --- | --- |
| 底部工具条 | `bottom` | [工具与模式](/zh/template-bottom) |
| 顶部工作栏、浮窗 | `surfaces` | [顶部工作栏与浮窗](/zh/template-surfaces) |
| 卡片与摘录菜单 | `selectionMenu`、`excerptShortcuts` | [卡片与摘录菜单](/zh/template-menu) |
| 插件入口 | `plugins`、`pluginConfigs`、`addon.` 代号 | [接入插件](/zh/template-plugins) |
| AI 任务 | `aiTasks` | [AI 任务](/zh/template-ai) |
| 进入场景界面后的行为 | `settings`、`home`、`review`、`resume`、`coach` | [行为设置](/zh/template-settings) |

该表只列常用字段，其余顶层字段见上文的字段表。
