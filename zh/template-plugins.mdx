插件安装到 MarginNote 之后，面板可以打开，但场景界面上不会出现任何入口。场景界面显示的入口由模板决定，因此插件若要出现在场景界面里，模板需要写上对应的配置。菜单的写法见[卡片与摘录菜单](/zh/template-menu)，模板包的结构见[最小打包](/zh/basic-package)。

插件接入模板涉及以下配置。

# 配置一览

以插件 `mn.hello` 为例：

```json template.json highlight={7 8} focus={7 8}
{
  "id": "u-hello",
  "name": "你好世界",
  "plugins": [
    "mn.hello"
  ],
  "pluginConfigs": {
    "mn.hello": { "v": 1 }
  },
  "bottom": {
    "modes": [{
      "id": "collect",
      "behavior": "write",
      "tools": ["tool.excerptBox", "addon.mn.hello.primary", "theme"]
    }]
  },
  "selectionMenu": {
    "cards": ["noteHighlight:", "addon.mn.hello.annotate:"]
  }
}
```

- `plugins` 是白名单，声明可以在场景界面中出现的插件。
- `pluginConfigs` 是模板给每个插件的一份配置。
- `addon.` 开头的条目把插件的按钮和菜单项呈现到界面上；本例里是一个工具条按钮和一条卡片菜单项。

`bottom.modes` 的完整写法见[工具与模式](/zh/template-bottom)，`selectionMenu` 的完整写法见[卡片与摘录菜单](/zh/template-menu)，本文只讲与插件有关的部分。

# 白名单

`plugins` 是一个字符串数组，取值为插件的 `addonid`。**只有写进这个数组的插件才能在场景界面中出现**，未写入该数组的插件不会出现。

系统场景模板的 `plugins` 数组恒为空，因此系统场景模板不会因为本机安装了插件而改变行为。

<Note>
  `plugins` 数组的内容来自插件的 `addonid`，该字段的说明见[场景插件基础](/zh/plugin-base)。
</Note>

# 模板给插件的配置

`pluginConfigs` 是一个对象，键为插件的 `addonid`，值为任意 JSON。模板把这份配置交给插件，插件无需另行存储。

这份配置属于模板：导出模板包、导入模板包、复制模板时都会一并携带。模板编辑器不解释该字段的内容，MarginNote 也不校验。

```json template.json
{
  "pluginConfigs": {
    "mn.vocab": {
      "pendingTag": "#Pending",
      "dailyLimit": 20
    },
    "mn.timer": {
      "minutes": 25
    }
  }
}
```

插件读取这份配置的途径如下。

## 经事件声明读取

插件在 `mnaddon.json` 的 `excerptClaim` 中配置 `configKey`，即可让某个标签的取值由模板覆盖：

```json mnaddon.json highlight={12} focus={12}
{
  "addonid": "mn.vocab",
  "title": "生词本",
  "version": "0.1.0",
  "author": "我",
  "marginnote_version_min": "4.5.0",
  "immersiveOnly": true,
  "panel": "index.html",
  "events": ["excerpt"],
  "excerptClaim": {
    "hashtag": "#X",
    "configKey": "pendingTag"
  }
}
```

此处的 `configKey` 为 `pendingTag`，因此该标签的取值为 `pluginConfigs["mn.vocab"]["pendingTag"]`。详见[事件系统](/zh/events)。

## 经接口读取

页面调用 `GET /immersive/template`，响应中的 `plugins` 数组列出当前模板放行的插件，每一项包含插件 id、放行状态与该插件的配置：

```javascript index.html
var r = await mn.api("/immersive/template");
if (r && r.available) {
  var list = r.plugins || [];
  var mine = null;
  for (var i = 0; i < list.length; i++) {
    if (list[i].addon === "mn.vocab") { mine = list[i]; }
  }
  if (mine && mine.allowed) {
    show(mine.config);
  }
}
```

<Note>
  取不到模板时响应里的 `available` 为假，原因在 `reason` 中，这种情况下不要循环重试。
</Note>

# 插件入口的写法

插件贡献的界面元素以 `addon.` 为前缀，由插件 id 与元素名拼成。写进工具行、顶部导航等位置的代号要匹配 `^addon\.[A-Za-z0-9_.-]+\.[A-Za-z0-9_]+$`；菜单项在末尾多一个冒号，写法见下文的“卡片菜单项”一节。

## 工具条按钮

工具条按钮的代号为 `addon.<插件id>.<名字>`，写入 `bottom.modes[].tools`：

```json template.json highlight={6} focus={6}
{
  "bottom": {
    "modes": [{
      "id": "collect",
      "behavior": "write",
      "tools": ["tool.excerptBox", "addon.mn.hello.primary", "theme"]
    }]
  }
}
```

其中的 `primary` 是 MarginNote 固定的元素名，表示该插件的胶囊按钮；按钮图标由插件在 `mnaddon.json` 的 `icon` 字段指定。

<Note>
  插件没有 `main.js` 时，MarginNote 按 `mnaddon.json` 中声明的 `panel` 合成外壳，工具条按钮、卡片命令与摘录事件都由清单声明。这种写法下不需要额外的代码文件。
</Note>

## 卡片菜单项

菜单项的代号为 `addon.<插件id>.<命令id>:`，**末尾的冒号不可省略**，写入 `selectionMenu` 的对应清单：

```json template.json highlight={6} focus={6}
{
  "selectionMenu": {
    "cards": [
      "noteHighlight:",
      "commentNote",
      "addon.mn.hello.annotate:"
    ]
  }
}
```

其中的 `annotate` 对应插件清单 `cardCommands` 中声明的命令 id。该命令的声明方式见[卡片与摘录菜单命令](/zh/menu-commands)。

## 插件里与模板里都要写入

命令要出现在菜单上，插件和模板两侧都需要写入：插件在 `mnaddon.json` 中声明这条命令，模板在 `selectionMenu` 中写入该命令的代号。缺少任何一侧，菜单上都不会出现。

| 插件里的声明 | 模板里的条目 | 结果 |
| --- | --- | --- |
| 声明 `cardCommands` | 未写入 `selectionMenu` | 菜单上没有该项 |
| 未声明 `cardCommands` | 写入 `addon.<id>.<cmd>:` | 菜单上没有该项 |
| 声明 `cardCommands` | 写入对应条目 | 菜单上出现该项 |

工具条按钮同理：插件在 `mnaddon.json` 中给出 `icon`，宿主合成 `addon.<插件id>.primary` 按钮，模板在 `bottom.modes[].tools` 中写入该代号。

# 安装后无法使用的情形

原因可能在插件一侧，也可能在模板一侧。

插件一侧的原因：插件清单中没有声明对应的按钮或命令。

模板一侧的原因：模板未把插件 id 写进 `plugins`，或未把对应条目写进 `bottom.modes[].tools` 与 `selectionMenu`，或代号格式写错（例如漏了菜单项末尾的冒号）。

<Warning>
  代号拼写错误与格式错误都不会报错，MarginNote 静默忽略。排查办法见[校验与排错](/zh/template-validate)。
</Warning>

# 运行中核对

面板可以读取当前模板，确认配置是否生效。响应里有每个插件的放行状态和配置内容：

```javascript index.html
var r = await mn.api("/immersive/template");
var plugins = r.plugins || [];
var found = false;
plugins.forEach(function (p) {
  if (p.addon === "mn.hello") {
    found = true;
    mn.log("allowed =", p.allowed, " config =", JSON.stringify(p.config));
  }
});
if (!found) {
  mn.log("当前模板的 plugins 里没有 mn.hello，界面上的入口不会出现");
}
```

这样能确认白名单与配置是否送达。响应里不含各份菜单清单，所以 `selectionMenu` 里的菜单项是否出现，只能在卡片菜单里人工确认。

<Note>
  `plugins` 中每个对象的 `addon` 为插件 id，`allowed` 表示放行状态，`config` 为模板交给该插件的配置内容。
</Note>

配置没有生效时，按[校验与排错](/zh/template-validate)定位原因。
