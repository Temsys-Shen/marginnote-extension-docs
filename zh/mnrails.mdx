MN Rails 是 MarginNote 插件的现代脚手架。为开发者提供方便的工程创建、构建、打包与部署功能，并提供了丰富的模板和脚手架，帮助开发者快速上手插件开发。

# 创建工程

使用 create 命令创建工程：

<CodeGroup>

```bash npm
npm create mn-rails@latest
```

```bash pnpm
pnpm create mn-rails@latest
```

```bash yarn
yarn create mn-rails
```

```bash bun
bun create mn-rails
```

</CodeGroup>


运行后将以交互式方式创建工程：
```
❮ pnpm create mn-rails@latest
? 选择框架
❯ React（React 19 + TypeScript + Vite）
  Vue（Vue 3 + TypeScript + Vite）
  Svelte（Svelte 5 + TypeScript + Vite）

↑↓ navigate • ⏎ select

```

## 非交互创建

全部参数可以通过命令行传入：

```bash
npx mn-rails@latest init my-addon \
  --framework react \
  --kind panel \
  --addonid com.example.my-addon \
  --author Example \
  --title 我的插件 \
  --package-manager pnpm \
  --no-git
```

显式指定的目标目录必须为空目录。省略目录参数且当前目录存在可见内容时，创建命令在当前目录下生成一个由用户确认的子目录。

## 框架与形态

| 框架 | 模板内容 |
| --- | --- |
| React | React 19、TypeScript 与 Vite |
| Vue | Vue 3、TypeScript 与 Vite |
| Svelte | Svelte 5、TypeScript 与 Vite |

工程提供的插件形态如下：

- 纯面板：即标准的`场景插件`，页面入口为 `index.html`，插件面板与菜单由 MarginNote 根据 `mnaddon.json` 生成。
- 混合形态：即混合`场景插件`与`经典插件`，包含 Web 页面与双端通信模块。见[面板之外](/zh/jsaddon)

`native/` 只出现在混合形态工程中。纯面板工程不创建这个目录，构建产物也不得包含根目录的 `main.js`。

主要文件与作用：

| 路径 | 作用 |
| --- | --- |
| `index.html` | 面板入口。 |
| `mnaddon.json` | 插件清单，声明插件标识、名称、版本、入口与事件。 |
| `eslint.config.mjs` | 共享 ESLint 配置。 |
| `eslint/framework.mjs` | React、Vue 或 Svelte 的框架规则。 |
| `src/` | React、Vue 或 Svelte 页面代码。 |
| `public/` | Vite 原样复制到产物根目录的静态资源。 |
| `template/template.json` | 场景模板配置。 |
| `template/localizations.json` | 场景模板名称的本地化内容。 |
| `vite.config.ts` | Vite 配置。 |

# 工程命令

工程提供以下脚本：

| 命令 | 作用 |
| --- | --- |
| `lint` | 运行 ESLint 与框架推荐规则。 |
| `lint:fix` | 自动修复可修复的 ESLint 问题。 |
| `typecheck` | 运行当前框架的类型检查。 |
| `check` | 依次运行 ESLint 与类型检查。 |
| `build` | 调用 Vite 构建页面，并检查插件目录与 `/pkg/` 引用。 |
| `package` | 生成 `.mnaddon` 与 `.mntemplate` 安装包。 |
| `sync` | 把构建产物同步到本机 MarginNote，并重启应用。 |
| `doctor` | 检查工程、构建产物与 MarginNote 环境。 |

<CodeGroup>

```bash npm
npm run lint
npm run lint:fix
npm run typecheck
npm run check
npm run build
npm run package
npm run sync
npm run doctor
```

```bash pnpm
pnpm lint
pnpm lint:fix
pnpm typecheck
pnpm check
pnpm build
pnpm package
pnpm sync
pnpm doctor
```

```bash yarn
yarn lint
yarn lint:fix
yarn typecheck
yarn check
yarn build
yarn package
yarn sync
yarn doctor
```

</CodeGroup>

# 构建与部署

首次构建：

<CodeGroup>

```bash npm
npm run build
```

```bash pnpm
pnpm build
```

```bash yarn
yarn build
```

</CodeGroup>

构建结果写入 `dist/`。`package` 与 `sync` 都要求 `dist/` 已经存在，并通过产物检查。

本地部署：

<CodeGroup>

```bash npm
npm run sync
```

```bash pnpm
pnpm sync
```

```bash yarn
yarn sync
```

</CodeGroup>

`sync` 执行以下步骤：

1. 检查 `dist/` 是否符合当前插件形态。
2. 定位本机 MarginNote 的插件目录。
3. 使用临时目录完成文件替换，并在失败时恢复原插件。
4. 重启 MarginNote。

本地部署只支持 macOS。

# 生成安装包

<CodeGroup>

```bash npm
npm run package
```

```bash pnpm
pnpm package
```

```bash yarn
yarn package
```

</CodeGroup>

安装包将生成至 `release/`：

- `<插件名称>-<版本>.mnaddon`：插件目录的压缩包。
- `<模板名称>-<版本>.mntemplate`：包含模板配置、本地化文件与插件文件的场景模板包。


模板配置的写法见[最小打包](/zh/basic-package)与[接入插件](/zh/template-plugins)。
