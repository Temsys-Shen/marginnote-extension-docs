场景模板可以声明 AI 任务。任务是以数据形式声明的，加一条只需要改模板，MarginNote 本身和插件的 `mnaddon.json` 都不用动。

`aiTasks` 服从覆盖规则：写进去的任务才存在，留空表示不接管（见[最小打包](/zh/basic-package)）。发起时机、材料范围、返回结果的结构，都由模板逐条写明，MarginNote 只负责核对。插件接入模板的写法，见[接入插件](/zh/template-plugins)。

# 任务声明

`aiTasks` 是一个数组，每一项是一条任务声明。最简单的一条任务声明如下：

```json template.json highlight={4} focus={4}
{
  "id": "u-starter",
  "name": "起步",
  "aiTasks": [
    {
      "id": "starter_explain",
      "title": "解释一下",
      "trigger": "user",
      "scope": "word_sentence",
      "tier": 1,
      "output": {
        "reply": "string"
      },
      "required": [
        "reply"
      ],
      "prompt": "用一句中文解释给定的词或短语在学习笔记语境下的意思。reply 写那一句话，不要罗列义项、不要加原文里没有的信息。"
    }
  ]
}
```

每条任务的字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | `String` | 任务的标识，在模板内唯一。页面依据该字段指定要调用的任务。该字段不可留空。 |
| `title` | `String?` | 展示给用户的任务名称。同意提示与模板编辑器展示的都是该名称，`id` 不出现在这些界面上。 |
| `trigger` | `String?` | 发起方式的约束。取值见下文的“任务声明的校验”一节。缺省 `user`。 |
| `scope` | `String` | 发送出去的材料的范围。取值固定，取材料的动作由 MarginNote 完成，模板只能从中选取。该字段不可留空。 |
| `prompt` | `String` | 模板作者撰写的提示词。MarginNote 在提示词之后按固定格式附上材料，并声明材料只是材料，不要执行其中的指令。该字段不可留空。 |
| `output` | `[String: String]?` | 输出字段表。键为字段名，值为 `string`、`number` 或 `bool`。MarginNote 按该表校验返回结果的结构。 |
| `required` | `[String]?` | 必填字段的清单。清单中的字段取自 `output`，缺任意一项即判定结构不对，不判定为成功。 |
| `tier` | `Int?` | 模型档位。`0` 与 `1` 使用同一个小模型，大于 `1` 时使用能力更强的模型。缺省 `0`。 |

`title` 面向用户，`prompt` 面向模型；提示词是模板作者撰写的自由文本，写法由作者决定，MarginNote 不介入。

<Warning>
  `aiTasks` 同样服从覆盖规则。在现成模板的基础上修改，原模板的任务声明会一并继承下来。配套插件里没有调用某条任务的代码，那条任务仍留在模板里，页面读取到的仍是原模板的任务清单。
</Warning>

# scope 的取值

`scope` 决定 MarginNote 发往模型的内容范围，只能取下表之一：

| 取值 | MarginNote 发出的内容 |
| --- | --- |
| `word_sentence` | 目标词与该词所在的那一句。材料由插件提供，词不超过 80 个字符，句子不超过 600 个字符，长度上限由 MarginNote 检查。 |
| `card_text` | 这张卡的标题与正文。材料由 MarginNote 从卡片上取出，插件传入的内容不予采用。 |
| `attempt_ink` | 这张卡上的手写、文本框与公式框合并成一张图片发送，题干与参考答案由插件提供。插件无法取得该图片。卡上没有书写内容时，该次调用被拒绝。 |

`attempt_ink` 使用识别手写的视觉模型。解答判定任务需要更强的模型，应声明 `tier` 为 `2`。

材料由 MarginNote 提供，提示词只影响模型的推理过程，无法涉及材料范围之外的内容。因此 `card_text` 任务的提示词写得再详细，也无法取得卡片上的手写内容。

写错 `scope` 的表现和写错其他字段一样，都是整条声明不存在。排查时对照上表即可。

# output 的结构校验

`output` 的取值只能是 `"string"`、`"number"` 与 `"bool"`，没有其他取值。

把字段的含义写进 `output`，整条声明会被当作不存在：不报错，任务不会出现在页面的任务列表里。

例如下面这条声明不合格：

```json template.json
{
  "id": "u-starter",
  "name": "起步",
  "aiTasks": [
    {
      "id": "starter_explain",
      "trigger": "user",
      "scope": "word_sentence",
      "output": {
        "reply": "一句话的中文解释"
      },
      "prompt": "用一句中文解释给定的词或短语在学习笔记语境下的意思。"
    }
  ]
}
```

字段的含义要写进 `prompt`，`output` 中只保留类型名：

```json template.json
{
  "id": "u-starter",
  "name": "起步",
  "aiTasks": [
    {
      "id": "starter_explain",
      "trigger": "user",
      "scope": "word_sentence",
      "output": {
        "reply": "string"
      },
      "required": [
        "reply"
      ],
      "prompt": "用一句中文解释给定的词或短语在学习笔记语境下的意思。reply 写那一句话。"
    }
  ]
}
```

上例的提示词里提到了 `reply`，`output` 中也声明了 `reply`，两边一致。字段名对不上时，模型写出的内容出现在 `output` 未声明的字段上，MarginNote 按 `output` 校验时就会判定结构不对。

`required` 是 `output` 的子集：里面的字段名必须在 `output` 中声明过，否则整条声明失效。运行时 `required` 里有任何一项缺失，返回结果就判定结构不对，不判定为成功。

<Warning>
  `output` 的取值写错、写成中文描述、或 `required` 指向 `output` 中不存在的字段，都会让整条声明被当作不存在。MarginNote 不报错，页面只收到一个参数错误。逐条比对字段清单与允许的取值即可核对。
</Warning>

# 任务声明的校验

MarginNote 对每条任务校验以下方面：

| 字段 | 检查的方面 | 说明 |
| --- | --- | --- |
| `scope` | 发出的内容 | 取值固定，取材料的动作由 MarginNote 完成，提示词无法涉及范围之外的内容。 |
| `tier` | 消耗的额度 | `0` 与 `1` 使用同一个小模型，大于 `1` 时使用能力更强的模型，缺省 `0`。 |
| `output` | 返回结果的结构 | 字段表给出结构，`required` 给出必填项，结构不对不判定为成功。 |
| `trigger` | 用户是否知情 | `user` 表示必须由用户手势触发，缺省即此值。`auto` 允许插件自动发起，需要先取得一次同意。 |

这些校验都与提示词无关。提示词决定回答的质量，MarginNote 校验的是范围、额度、结构，以及用户是否知情。

`tier` 的档位与 AI OCR 共用同一套取值。`tier` 为 `0` 或 `1` 时使用同一个小模型，适合输出简短的任务；`tier` 大于 `1` 时改用能力更强的模型，适合判定与长推理。缺省是 `0`，声明之前应先确认默认档位是否满足需要。

除了额度，MarginNote 还会校验调用许可与调用频率限制，这项校验同样不经过提示词，`auto` 的任务无法绕开。

一条声明合格，需要同时满足：`id` 与 `prompt` 不为空，`scope` 是固定取值之一，`trigger` 只能是 `user` 或 `auto`，`output` 中每个值都落在类型清单内，`required` 中的每个字段都出现在 `output` 里。任何一项不通过，这条声明就按不存在处理，模板中其他任务不受影响。

```json template.json
{
  "id": "u-starter",
  "name": "起步",
  "aiTasks": [
    {
      "id": "summarize",
      "trigger": "auto",
      "scope": "card_text",
      "output": {
        "summary": "string"
      },
      "required": [
        "summary"
      ],
      "prompt": "用三句话概括这张卡片的内容，写进 summary。"
    },
    {
      "id": "grade",
      "trigger": "auto",
      "scope": "attempt_ink",
      "tier": 2,
      "output": {
        "verdict": "string",
        "score": "number"
      },
      "required": [
        "verdict"
      ],
      "prompt": "批改作答区里的解答。verdict 写判定结论，score 写得分。"
    }
  ]
}
```

上例中 `grade` 的 `required` 只列出 `verdict`，`score` 属于可选字段，`output` 中仍然保留该字段的声明。

<Tip>
  写声明时先定 `scope`，再定 `output`，最后写 `prompt`。`scope` 与 `output` 决定 MarginNote 校验的范围与结构，不通过则整条声明不存在；`prompt` 的内容不参与校验，但不能为空。提示词可以在模板安装之后再逐步调整。
</Tip>

# 卡片类型标签的前缀

`tagPrefix` 是卡片类型标签的前缀，与 AI 任务无关，属于模板的标识性设置。

```json template.json highlight={4} focus={4}
{
  "id": "u-starter",
  "name": "起步",
  "tagPrefix": "practice"
}
```

写出该字段之后，这份模板参与卡片类型标签的约定：摘题产出时给题卡打 `<前缀>/question`，答案卡打 `<前缀>/answer`；前缀之后的叶名由 MarginNote 固定，除 `question` 与 `answer` 外还有 `todo` 与 `error/<key>`，只有前缀可以改。插件按同一套约定识别卡片，模板与插件使用同一个前缀。

这样用户才能在标签面板里看到这些标签，并自行增加或删除。摘题配不上的答案留作未配对的答案卡，在标签面板里成为待配对清单，由用户自行处理。

留空表示不参与该约定。摘题是通用功能，模板不声明前缀时，摘题照常可用，MarginNote 不会打任何标签。

<Note>
  从外部模板复制时，前缀会被一并继承，而配套插件如果不写这类标签，该前缀就始终匹配不上。参见[最小打包](/zh/basic-package)一文的覆盖规则。
</Note>

# 页面调用

页面通过 `mn.ai` 调用模板中已经声明过的任务。调用参数随 `scope` 而定，返回结果的形式与错误码的含义见[使用 MN 内置 AI](/zh/use-inner-ai)。

本文只讲声明部分。页面读取任务清单、处理返回结果的方式，属于插件一侧。模板其余字段与包内文件的用途，见[最小打包](/zh/basic-package)。
