配置写错时，模板不会报错。字段名或代号写错时，MarginNote 静默忽略该条目，对应的按钮不会出现；字段的取值类型写错时，整份模板无法解析，MarginNote 回退到默认模板。

界面上的条目缺失时，成因可能是配置写错、尚未生效，或功能本身不可见。合理的顺序是先按本文自查，再导入 MarginNote 确认。

# 静默忽略的成因

上述各类错误在界面上的表现相同：某个条目没有出现。区别在成因。

## 字段名不在所属位置内

每个位置只接受属于该位置的字段。字段名不在该位置的字段表里，读取时就被丢弃。顶层字段也一样：`template.json` 顶层拼错的字段名不会报错，只是不起作用。

拼写错误是常见成因，例如把 `dockPinned` 写成 `dockPinnd`。字段的层级放错同样常见，例如把 `dockPinned` 写进 `bottom`，该字段不属于 `bottom`，写入的值不会被读取。旧字段的说明见[顶部工作栏与浮窗](/zh/template-surfaces)。

## 代号不在该位置的合法代号清单内

每个清单位置都有一份固定的代号清单，清单之外的代号被静默忽略。

拼写错误是常见成因，例如把 `act.doc.toggle` 写成 `act.doc.toggl`。

## 代号存在，但放错了位置

这一类问题最难发现：该代号在另一处确实合法，写在该位置时表面上看不出错误。

例如 `theme` 是合法代号，能放进 `bottom.modes[].tools`，写进 `surfaces.nav` 就会被忽略。

书写时看到的只是一个合法的代号字符串，因此放错位置只能通过对照清单发现。

# 取值类型写错

字段的取值类型与字段表不符时，MarginNote 无法解析整份模板。出错的不只是该字段：整份模板都被丢弃，界面回到默认模板。

常见情形是字段的取值形式与字段表不符。例如 `dockPinned` 写成对象（该字段只接受字符串数组）、`plugins` 写成字符串（该字段只接受数组）、`settings.global` 中某一项的值写成对象（取值只能是布尔值、数字或字符串）。

# 自查清单

写完 `template.json` 后，逐项对照：

1. 字段名：对照各篇的字段表，包括顶层字段。
2. 代号的拼写与所在位置：对照[代号词汇表](/zh/template-vocabulary)，每个位置的清单是固定的。菜单条目的代号以模板编辑器列出的为准。
3. 插件条目：代号格式是 `addon.<插件id>.<名字>`，菜单项末尾要带冒号，见[接入插件](/zh/template-plugins)。
4. `settings.global` 的键：必须取自词汇表里的能力目录。
5. `aiTasks`：`id` 与 `prompt` 不为空，`scope`、`trigger` 取固定值，`output` 的值只能是类型名，`required` 里的字段都在 `output` 中，见[AI 任务](/zh/template-ai)。
6. 字段类型：清单里的元素都是字符串，其余字段的类型与字段表一致。

# 现象与成因对照

| 界面现象 | 可能成因 | 排查方向 |
| --- | --- | --- |
| 工具行里预期的工具没有出现 | 代号拼错，或该代号属于其他位置 | 对照词汇表核对拼写与所属位置 |
| 按钮只出现在 `更多` 弹层，工具行上没有 | 该条目写在 `overflow` 里 | 把该条目移入 `tools` |
| 顶部导航缺少某个按钮 | 代号拼错，或写在了 `surfaces.nav` 之外 | 核对 `surfaces.nav` 里的代号 |
| 常驻浮球没有出现在右缘 | 漏写 `dockPinned`，或写进了旧字段 `dock` | 核对字段名 |
| 卡片多选工具栏缺少操作 | 代号属于底部工具条或能力目录，写在了 `surfaces.multiSelect` | 对照词汇表“卡片多选工具栏”一节 |
| `settings.global` 的预设没有变化 | 键不在能力目录内，或该项由学习集单独配置 | 对照词汇表的能力目录，见[行为设置](/zh/template-settings) |
| 某个设置项完全不起作用 | 顶层字段名拼错，或字段放错层级 | 核对顶层字段名 |
| 整份模板都不生效 | 某个字段的取值类型写错 | 对照字段表核对取值类型 |
| 插件按钮出现，点击没有响应 | 按钮的行为由插件实现，与模板配置无关 | 检查插件本身 |

# 确认模板真的生效

自查清单只能确认配置写得正确。导入之后，还需要确认 MarginNote 加载的确实是该模板：导入模板包，切换到这份模板，进入场景界面，逐项对照预期。

带插件的模板可以让面板读取当前模板，确认白名单与配置是否送达，写法见[接入插件](/zh/template-plugins)的“运行中核对”一节。读取结果不含菜单清单，菜单项是否出现，只能在卡片菜单里人工确认。
